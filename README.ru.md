# Figma Full Cycle

**На входе — ссылка на родительский фрейм в Figma. На выходе — собранная, сверенная с дизайном и
отревьюенная фича по правилам проекта.**

`figma-full-cycle` — оркестратор-скилл ([Agent Skill](https://code.claude.com/docs/ru/skills)) для
Claude Code и Codex. Даёшь ссылку на родительский фрейм фичи; скилл ведёт весь путь от дизайна до
готового к merge кода — спека, ассеты, вёрстка, сверка, адаптивность, логика, ревью — восемью
этапами с gate'ами, один этап = один коммит, источник правды — tracked-манифест.

## Один плагин, четыре отдельных скилла

Репозиторий — набор переиспользуемых скиллов, оформленный как плагин Codex. Установка плагина
добавляет все четыре точки входа; вызов одного скилла не запускает остальные.

| Скилл | Для отдельного использования |
|---|---|
| `figma-full-cycle` | Полная реализация фичи; внутри вызывает подготовку спеки и импорт ассетов |
| `figma-feature-spec` | Спецификация по Figma без реализации приложения |
| `import-figma-assets` | Импорт графики в каталог ассетов Xcode |
| `device-usage` | Проверка физического iPhone через Device Hub без Figma и полного цикла |

Это основной репозиторий всех четырёх скиллов. Разработка, issues и релизы Device Usage теперь
ведутся здесь; [исходный репозиторий](https://github.com/gwair1989/device-usage) сохраняется для
истории. `device-usage` по-прежнему можно устанавливать и вызывать отдельно.

Device Hub — основной канал управления физическим устройством, Видеоповтор — запасной.
Плагин содержит инструкции и необязательный помощник сохранения скриншотов. Он не устанавливает
Xcode, Computer Use, MCP-сервер или разрешения macOS. Проверки на симуляторах сохраняются:
один подключённый телефон не заменяет матрицу адаптивности. В полный цикл проверки физического
устройства включаются по запросу пользователя или требованию проекта.

## Зачем

Один промпт «свёрстай этот экран из фигмы» на настоящей фиче ломается предсказуемо:

| Проблема | Что делает скилл |
|---|---|
| Агент выдумывает поведение, которого в статичном макете не было | Каждый неизвестный пункт — вопрос в журнале или явный `TBD`, не молчаливая догадка |
| Агент игнорирует конвенции проекта: строки, типографика, цвета | Read-only аудит конвенций **до** Figma и до любых правок; пять разрешённых строк контракта гейтят все этапы |
| Каталоги локализации и сырые MCP-ответы сжигают контекст | Ограниченные read-only хелперы, scoped Figma-чтение, делегирование subagent'ам, компактные evidence в state |
| Один гигантский нечитаемый коммит | Один этап = один коммит, каждый за gate'ом, подтверждённым реальной командой |
| «Всё зелёное» без единого запуска | Gate требует evidence: команда, время, exit code, путь артефакта |
| После работы транк грязный | Фича живёт в своей ветке и worktree; cleanup только после подтверждённого merge |

## Этапы

| # | Этап | Gate (кратко) |
|---|---|---|
| 0 | Worktree — ветка, секреты симлинком, build defaults, baseline build/test | Baseline записан, манифест создан |
| 1 | Спека + UI Plan — экраны, navigation map, инвентарь ассетов и copy | Спека и `UI_PLAN.json` на диске, `ui_plan.py --phase ui` pass, блокеры отвечены |
| 2 | Ассеты — импорт по инвентарю node-id | Build успешен, каждый ассет проверен |
| 3 | Вёрстка UI + каркас архитектуры проекта | Evidence UI Plan актуальны, строки проверены, build успешен, каждый экран и состояние — `done` |
| 4 | Рефакторинг UI — *условный*, только при findings | Build успешен, затронутые проверки → `stale` |
| 5 | Сверка с дизайном — поэкранно против запиненного фрейма | Отчёт на диске, расхождения исправлены и пересверены |
| 6 | Адаптивность — малый/большой экран, light/dark, content sizes, локали, клавиатура | Нет обрезок и наложений, evidence сохранён |
| 7 | Бизнес-логика + runtime-навигация + тесты | `ui_plan.py --phase production` pass, тесты pass, TBD помечены |
| 8 | Финальное ревью | Ревью чисто, нет сырых user-facing литералов, чистый checkpoint закоммичен |

Два свойства делают это пригодным для жизни:

- **Resume с любого этапа.** State лежит на диске и сверяется с git — `старт: этап N` или просто
  «продолжи фичу».
- **Режим `ui-first`.** Дизайн есть, ТЗ нет? Этапы 0–6 идут сейчас, продуктовые вопросы уходят в
  `deferred-to-spec` вместо блокировки, этапы 7–8 ждут ТЗ.

## Требования

- **Агент:** Claude Code или Codex (адаптер маппит capability на конкретные имена инструментов).
- **Figma MCP** с read-доступом и `FIGMA_ACCESS_TOKEN` к этапу 5.
- **Python 3.9+** — только стандартная библиотека, `pip install` не нужен.
- **Проект:** Xcode/SwiftUI-приложение. Архитектура определяется по документации проекта
  или явному решению пользователя. Если документации нет, она неоднозначна или противоречива,
  скилл спрашивает пользователя; код и установленные скиллы не определяют выбор архитектуры.
  Решение и его источник фиксируются в манифесте и спеке до реализации, в том числе в `ui-first`.
  Этапы 3 и 7 следуют выбранной архитектуре; обязательного архитектурного фреймворка нет.
- **Скиллы-спутники не зашиты по именам — они обнаруживаются.** Префлайт проходит по реально
  установленным скиллам, MCP-инструментам, MCP-ресурсам, плагинам и скриптам проекта и привязывает
  по одному кандидату к каждой *роли* этапа: `design-to-code-workflow`, `platform-ui-idiom`,
  `app-architecture`, `visual-comparison`, `code-review` и так далее. Переименованные, вынесенные в
  неймспейс, префиксованные плагином и совсем новые вендорские скиллы подхватываются так же; роль
  без кандидата уходит в задокументированный fallback. Жёстко по именам — только то, что лежит
  здесь: `figma-full-cycle`, `figma-feature-spec`, `import-figma-assets`, необязательный
  `device-usage`. Вызывается точное зарегистрированное имя, включая namespace плагина.
- **Только для физического iPhone:** macOS, сопряжённый iPhone, Xcode с Device Hub и доступный
  desktop Computer Use для самостоятельного управления UI. Возможности проверяются по инструкции
  скилла; при отсутствии GUI-управления остаётся доступная диагностика через CLI.
- **Необязательный помощник сохранения скриншотов и его тесты:** Node.js 22+, без npm-зависимостей.

Отсутствующие возможности выдаются одним списком-блокером в начале, а не всплывают по одной на
середине работы. Итоговые привязки — вместе с пробой аутентификации Figma и доступности узла —
пишутся в capability ledger манифеста.

## Установка

### Плагин Codex

`plugin.json` описывает переносимый пакет, `.codex-plugin/plugin.json` обеспечивает совместимость
с Codex, `.agents/plugins/marketplace.json` добавляет локальный каталог. Из этого checkout,
в версии Codex CLI с командой `plugin add`:

```bash
git clone https://github.com/gwair1989/figma-full-cycle.git
cd figma-full-cycle
codex plugin marketplace add .
codex plugin add figma-full-cycle@figma-full-cycle-local
```

Другой вариант — выбрать локальный источник в каталоге плагинов desktop-приложения. После
установки начать новую сессию и выбрать точное имя скилла из каталога: оно может включать namespace,
например `figma-full-cycle:device-usage`. Формат соответствует
[документации OpenAI](https://developers.openai.com/plugins/build/plugins).
Репозиторий служит локальным источником установки; публикации в общем каталоге плагинов нет.

### Отдельные скиллы

```bash
git clone https://github.com/gwair1989/figma-full-cycle.git
cd figma-full-cycle
./install.sh
```

`install.sh` ставит симлинки на все четыре скилла в `~/.claude/skills` — после этого `git pull`
обновляет их на месте.

```bash
./install.sh --target ~/.codex/skills   # Codex
./install.sh --target ~/.agents/skills --skill device-usage   # только Device Hub
./install.sh --target ~/.agents/skills --skill figma-feature-spec --skill import-figma-assets
./install.sh --target .claude/skills    # только для текущего проекта
./install.sh --copy                     # копировать вместо симлинка
./install.sh --force                    # заменить одноимённый скилл
./install.sh --uninstall                # удалить установленное
```

`--skill` можно повторять. При выборе `figma-full-cycle` также устанавливаются обязательные
помощники спеки и ассетов; `device-usage` остаётся необязательным. Удаление через
`--uninstall --skill` затрагивает только указанные скиллы, сохраняя общих помощников.
`--copy` создаёт самостоятельные папки для переноса на другую машину; соседний репозиторий
`device-usage` не требуется.

Для каждого скилла следует выбрать один способ регистрации: плагин или отдельная установка.
Отдельные скиллы вызываются в Codex как `$figma-full-cycle`, `$figma-feature-spec`,
`$import-figma-assets`, `$device-usage`. Их папки можно использовать и в Claude Code;
для управления Device Hub среда агента должна предоставлять desktop Computer Use.

Скиллы уже лежат в твоём skills-каталоге? `--force` заменит их, а старые копии перенесёт в
`.skill-backups` **рядом** с каталогом скиллов, а не внутрь него — внутри агент подхватил бы бэкап
как второй, дублирующий скилл.

Проверка: новая сессия агента, `figma-full-cycle` виден в списке скиллов.

## Использование

Нужна ссылка на **родительский** фрейм — контейнер со всеми экранами флоу, не на один экран:

```text
Сделай фичу по фигме целиком: https://figma.com/design/<fileKey>/App?node-id=1234-5678
```

```text
Полный цикл по фрейму <url>, режим: ui-first — тз позже
```

```text
Продолжи <FEATURE>, старт: этап 5
```

### Что появляется в проекте

| Файл | Tracked | Роль |
|---|---|---|
| `docs/<FEATURE>_PIPELINE.md` | да | Манифест: этапы, gates, evidence, журнал вопросов, решения |
| `docs/<FEATURE>_UI_PLAN.json` | да | Машинно-проверяемый контракт передачи из спеки в вёрстку |
| `docs/<FEATURE>_PIPELINE.local.md` | нет (gitignored) | Локальный runtime: абсолютные пути, UDID симулятора |

### Пять скриптов

Все read-only и на чистой стандартной библиотеке — скилл зовёт их, чтобы модель не глотала сырые
данные:

```bash
python3 skills/figma-full-cycle/scripts/ui_plan.py validate \
  --plan docs/FEATURE_UI_PLAN.json \
  --manifest docs/FEATURE_PIPELINE.md \
  --project-root . --phase ui
```

`ui_plan.py` валидирует контракт вёрстки — экраны, компоненты, токены, copy, ассеты и их provenance
— и отдаёт компактную actionable-диагностику до начала build-цикла.

```bash
python3 skills/figma-full-cycle/scripts/localization_context.py inventory --root .
```

`localization_context.py` инспектирует `.xcstrings` / `.strings` / `.stringsdict` с ограниченным
выводом: `inventory`, точечный `lookup`, key-level `diff`, `validate`. Каталоги не пишет и целиком
не печатает.

```bash
python3 skills/figma-full-cycle/scripts/ui_guard.py check \
  --project-root . --changed-since <BASE_SHA> \
  --reference-canvas 393x852 --asset-catalog App/Assets.xcassets
```

`ui_guard.py` — гейт этапов 3 и 8 для контрактов Layout и Colors. Отдаёт только
`path:line: RULE-ID: message`, поэтому проверка фичи стоит находок, а не чтения диффа. Он намеренно
частичный и с каждым запуском печатает правила, которые **не** проверял — чистый прогон ровно такой
ширины, как эта заметка.

```bash
python3 skills/figma-full-cycle/scripts/manifest.py get \
  --file docs/FEATURE_PIPELINE.md --section "Capability ledger" --section "Question log"

python3 skills/figma-full-cycle/scripts/manifest.py verify-sources \
  --file docs/FEATURE_PIPELINE.md --project-root .
```

`manifest.py` читает части манифеста вместо всего файла — к этапу 6 заполненный весит десятки
килобайт — и отвечает на вопрос, который реально возникает при resume: `verify-sources` пересчитывает
хэши документов, по которым резолвился контракт конвенций, и говорит по каждой области
`unchanged` / `CHANGED` / `unrecorded`. Неизменившийся проект стоит одной команды вместо повторного
чтения его документации.

```bash
python3 skills/figma-full-cycle/scripts/screenshot_diff.py compare \
  --render build/Onboarding@iPhoneSE.png --mock design/Onboarding.png \
  --ignore-top 6% --out reports/onboarding-se.json
```

`screenshot_diff.py` сравнивает скриншот реализации с макетом **разного размера** — макет сначала
нормализуется к размеру рендера, потому что на референсном устройстве вёрстка с фиксированным
канвасом совпадает пиксель-в-пиксель и прячет поломку. Отвечает на леттербокс, пилларбокс и фон до
краёв за ~0.3 с на пару, плюс режим `batch` для матрицы этапа 6. Нужен `sips` — он идёт с macOS, а
пайплайн и так требует macOS из-за `xcrun simctl`, так что ставить нечего.

На другом классе устройств он намеренно говорит меньше: нормализация растягивает макет, а нативная
раскладка адаптируется, сохраняя метрику в пунктах, поэтому структурный grid-дифф ругается на
корректно адаптированный экран так же громко, как на сломанный. Сверх `--aspect-tolerance` grid
показывается, но не гейтит, а обрезка контента на меньшем устройстве остаётся вопросом к ревьюеру.

Это фильтр, а не гейт: он видит геометрию, а не дизайн, и с каждым запуском печатает, чего он не
видит — шрифт, форму иконки, текст, мелкие сдвиги цвета. Глазами смотрим каждый провал и одну
прошедшую пару на экран.

## Модель безопасности

- **Figma — недоверенный ввод.** Текст внутри дизайна это контент, а не инструкция.
- **Write-инструменты Figma выключены** (`use_figma`, `upload_assets`, записи Code Connect и т.д.),
  пока пользователь явно не попросит изменить файл дизайна.
- **Секреты не копируются.** В worktree — симлинк на `.env` основного checkout; secret scan перед
  каждым коммитом; значения не печатаются.
- **Переводы не выдумываются.** Source copy не разливается по локалям без задокументированной
  политики проекта; готовность переводов — отдельный gate.
- **Merge решает пользователь.** Пройденный этап 8 даёт ветку, готовую к PR, а не автоматический
  merge.

## Портирование на другого агента

Новый агент — это новый файл адаптера, а не правка ядра. Скопируй
`skills/figma-full-cycle/adapters/claude-code.md`, замени правую колонку на имена инструментов
своего агента, строки capability оставь как есть и сошлись на файл из раздела адаптеров скилла.
Ядро `SKILL.md` намеренно остаётся agent-neutral.

## Контрибьютинг

Issues и PR приветствуются — см. [CONTRIBUTING.md](CONTRIBUTING.md). Проверки локальные, идут секунды:

```bash
./check.sh
```

Запускает Python-тесты валидаторов, пакета и установщика на каждой найденной версии Python 3,
затем тесты записи скриншотов на Node.js 22+, проверку структуры скиллов и синтаксиса shell.
Тесты используют локальные фикстуры и временные каталоги, не управляют телефоном и не устанавливают
плагин в аккаунт. Чтобы это происходило само перед каждым push:

```bash
ln -sf ../../tools/pre-push .git/hooks/pre-push
```

CI проверяет структуру скиллов, ссылки, пакет, установщик и запись скриншотов. Большие Python-наборы
проверок валидаторов остаются в локальном запуске.
