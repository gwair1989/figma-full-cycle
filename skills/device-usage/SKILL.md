# Device Usage

Сначала определить среду агента и доступные средства управления по [agent-compatibility.md](references/agent-compatibility.md). Скилл работает как набор инструкций для Codex и Claude Code; установка не добавляет Computer Use или разрешения macOS. Отвечать пользователю на языке его запроса.

Проверять реальный iPhone с Mac через **Device Hub как основной канал**. **iPhone Mirroring («Видеоповтор») — запасной канал** при недоступности Hub или для независимой перепроверки действия. Явный выбор пользователя имеет приоритет. Скилл не зависит от репозитория, приложения, bundle ID или модели iPhone.

Работу может полностью выполнить текущий агент; делегирование необязательно. При параллельной работе у физического target и его управляющей сессии должен быть один владелец ввода: только он навигирует, меняет канал или устанавливает/запускает приложение. Перед передачей управления завершить текущее действие, сохранить checkpoint с target/build/channel, экраном, данными и активными collectors, явно освободить управление. Новый владелец получает свежие AX/screenshot. Остальные агенты могут анализировать сохранённые evidence без управления телефоном.

## Подготовка и маршрутизация

1. Зафиксировать physical target, iOS/macOS/Xcode, приложение/version/build, источник установки, исходное состояние и разрешённые изменения данных. Для inline pickers учитывать автоматическое сохранение: открытие пустого поля способно сразу подставить значение без Save/Cancel. Перед входом записать исходное значение и разрешённый scope тестовых данных, после — фактическую мутацию. Отдельно проверить deployment, живое изображение и ввод: USB или видимый экран не подтверждают кликабельность.
2. При первичной настройке, смене Xcode/iOS или отказе канала прочитать [device-hub.md](references/device-hub.md): версии, pairing, capabilities, инспекторы и известные ограничения. Для UI прочитать [control.md](references/control.md): CUA-жесты, координаты, доступная нативная иерархия, ввод текста и recovery. Для каруселей и боковой прокрутки использовать раздел [горизонтальная прокрутка](references/control.md#горизонтальная-прокрутка).
3. Если нужны установка или логи, прочитать [deploy-and-logs.md](references/deploy-and-logs.md). Уже установленное приложение можно тестировать без пересборки; права debugger/container проверяются отдельно.
4. Для повторяемой регрессии или дополнительного инструмента прочитать [automation.md](references/automation.md). Подготовка XCTest/WDA не является обязательным условием исследовательского прохода через Hub.
5. При сохранении screenshots прочитать [evidence.md](references/evidence.md): нативный capture устройства или кадр CUA, MIME по байтам, нейтральные ID, manifest, приватность и необязательный capture-helper. Координаты нативного кадра не переносить в окно CUA.

Использовать доступные инструменты и их текущую документацию. CUA-примеры применяются только при наличии совместимого API; Simulator-only tap/swipe не становятся device-командами после замены идентификатора.

При потере ввода Hub агент самостоятельно выполняет [ограниченное восстановление через Computer Use](references/control.md#hub-общий-отказ-ввода) в рамках текущего прогона, без повторного запроса подтверждения на reconnect/relaunch. Если Computer Use недоступен или не может управлять Hub, явно сообщить причину и дать пользователю конкретные оставшиеся шаги для ручного выполнения; не выдавать рекомендацию за выполненное восстановление.

Сохранять уже выданные разрешения в контексте прогона; отдельную покупку, согласие или новый доступ оценивать по фактическому действию и правилам CUA. Restore сам по себе не разрешает новую покупку или доступ к Health.

## Быстрая проверка одной правки

Если запрос ограничен одним control или маршрутом, выполнить точечный прогон. Проверки среды, исходных данных и границ разрешённых изменений остаются обязательными; известные target/build достаточно подтвердить. Уже установленное приложение не требует пересборки ради самого прогона.

1. Зафиксировать проверяемое поведение, ожидаемый результат и нужный начальный экран; открыть его через Hub. Mirroring использовать по обычным правилам запасного канала.
2. Получить свежее наблюдение, выполнить одно действие и подтвердить конечное состояние. Проверить также видимые подписи, обрезку, наложение и расположение элементов. Загрузку или анимацию перепроверить после перехода.
3. Сохранить фактический результат/evidence, категорию наблюдения и статус маршрута по [правилам результата](references/deploy-and-logs.md#категории-наблюдений). При отказе ввода применить ограниченную диагностику из `control.md`.
4. Завершить после подтверждения результата, ошибки или blocker; зафиксировать изменения данных, остановить свои collectors и завершить свои ненужные сессии. Покрытие ограничить этим маршрутом, остальные ветки обозначить `not-run`.

## Проход экранов

Составить карту согласованных маршрутов. Состояния авторизации, permissions, подписок, загрузки и ошибок учитывать отдельно. Наличие существующих данных может делать пустые/onboarding-состояния недостижимыми без отдельной подготовки.

Рабочий цикл: **свежее наблюдение → одно действие → проверка результата → checkpoint**. Для evidence: **capture → просмотр сохранённых bytes → annotate**. После sheet/resize/rotation дождаться стабильной геометрии цели. Mac AX может не содержать iOS-элементов; переходы подтверждать screenshot.

До диагностики заполнить матрицу ввода из [control.md](references/control.md): возможность Apple, выразимость текущим API, фактически проверенный результат. После повторного no-op сравнить тот же ввод в другом контейнере; смена канала должна отвечать на конкретный вопрос. Повторяемый перелёт через середину — предел точности текущего метода: остановить подбор всё более коротких drag и выбрать различающую проверку.

Для длинного экрана выбрать container и видимые якоря. Пройти вниз с перекрытием, подтвердить конец содержимым, затем проверить обратный ход. Число жестов и success инструмента не доказывают покрытие. Если drag пропускает промежуточные поля, отметить частичное покрытие и применить более управляемый метод.

В grid учитывать оба столбца, в карусели — каждую карточку и горизонтальные границы отдельно от вертикального конца страницы. Подтверждать карусель цепочкой стабильных кадров с общим соседним элементом; первый и последний кадры не доказывают покрытие середины. В auto-advance stories отмечать фактически увиденные слайды и пропуски; время записи документации не является наблюдением контента. Просмотр шаблона и полный контентный аудит — разные уровни покрытия.

| Симптом | Действие |
| --- | --- |
| Hub: wheel-scroll не движет длинный экран | Проверить touch-drag внутри контента и обратный drag |
| Hub: живое изображение, но app click и системный Home дают no-op | Проверить [общий отказ ввода Hub](references/control.md#hub-общий-отказ-ввода) до дальнейших scroll-проб |
| Mirroring: два scroll no-op после sheet | Проверить overlay/край; Home → App Switcher → та же карточка; контрольный scroll |
| AX не изменился | Проверить изображение iPhone |
| Текст не появился | Подтвердить фокус; проверить одиночную клавишу, а не повторять слепо typeText |
| «iPhone используется» в Mirroring | Владелец блокирует телефон; затем проверить соединение |
| Hub показывает lock screen / app restriction | Штатное действие владельца; зафиксировать blocker |
| CUA сообщает Mac locked | Владелец разблокирует Mac; свежий кадр, затем повтор того же неудавшегося контрольного действия |

После ограниченного recovery подтвердить тот же ввод. Если не восстановился — другой подготовленный канал либо конкретный blocker. Различать сбой приложения, геометрии, метода ввода, системное ограничение и stale log stream; причину не объявлять установленной без контроля.

## Результат

Для каждого маршрута записать entry/exit, build/channel, ожидаемый и фактический результат, проверенные направления scroll, evidence и recovery. Статусы: passed, failed, blocked, not-run; отдельно указывать coverage, например `status=blocked, coverage=partial` при пропущенной середине. [Категорию наблюдения](references/deploy-and-logs.md#категории-наблюдений) записывать отдельно от статуса маршрута: функциональная/визуальная ошибка, переходное состояние, ожидаемое поведение или неожиданное завершение. Найденные баги сохранять с шагами воспроизведения и уверенностью в причине.

Завершение: каждый согласованный маршрут имеет результат или blocker; зафиксированы непроверенные ветки, итоговые данные/экран/сборка, остановлены свои collectors и перечислены оставшиеся sessions, backups и caches. Сверить оставленные изменения с исходными значениями, включая defaults после открытия редакторов и прогресс контента. Полный проход заявлять только в пределах этой матрицы.
