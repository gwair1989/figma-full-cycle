# Совместимость с агентами

Skill — инструкции и необязательный evidence-helper. Он не устанавливает драйвер управления, MCP-сервер, hooks или права доступа. Использовать только tools, предоставленные текущей средой, с их фактическими разрешениями. Правила tools и выбранные пользователем ограничения имеют приоритет над примерами скилла.

## Codex

Вызов standalone skill: `$device-usage`. В Codex desktop при наличии `cua_repl` выбрать приложение, прочитать возвращённую документацию и далее использовать `cua` по [control.md](control.md). Наличие Codex CLI или умение выполнять shell само по себе не означает наличие desktop Computer Use.

В составе плагина имя может иметь namespace пакета, например `figma-full-cycle:device-usage`. Выбирать точное имя из каталога текущей сессии. Этот скилл можно вызывать отдельно от остальных скилов пакета: ссылка на Figma и запуск полного цикла ему не нужны.

## Claude Code

Standalone skill в `~/.claude/skills/device-usage/` или `.claude/skills/device-usage/` вызывается `/device-usage`. При установке через плагин namespace зависит от имени пакета, например `/device-usage:device-usage` в исходном плагине. Проверять фактическое имя в списке доступных skills текущей версии Claude Code.

1. Проверить предоставленные tools: нужен доступ к нативным приложениям Mac, свежему экрану и вводу. Browser-only automation не управляет окном Device Hub.
2. Если desktop Computer Use предоставлен средой или настроенным MCP, прочитать его контракт и выполнить observe → act → verify средствами этого API. Имена `cua`, `hub` и `nodeRepl` из примеров Codex не являются встроенными API Claude Code.
3. Если Computer Use отсутствует, продолжать разрешённую read-only диагностику через `devicectl` и анализ локальных файлов. Для UI-действий и восстановления ввода дать владельцу конкретные шаги из [control.md](control.md#hub-общий-отказ-ввода), сохранить checkpoint и явно указать, что самостоятельная UI-проверка недоступна.
4. Не добавлять скрытую инъекцию событий, AppleScript или разрешения macOS вместо отсутствующего Computer Use. Если пользователь отдельно выбирает другой инструмент, применять его документацию и согласованный scope.

Восстановление ввода самостоятельно выполняется только при подходящем доступном tool и в разрешённом сценарии. Unlock/Trust/новый доступ владельца не подменяются подтверждением агента. Ответ пользователя о ручном успехе хранить как `reported-by-user`, пока агент не может сам проверить результат.

## Переносимые пути и evidence

Все ссылки внутри skill относительны его `SKILL.md`. Абсолютный путь к helper получать из текущей установки; не предполагать имя пользователя, `~/.agents`, `~/.claude` или расположение plugin cache.

`capture-evidence.mjs` работает с объектом, у которого `getScreenshot({emit:false})` возвращает `Uint8Array`. Такой объект не появляется от установки плагина. Если runtime его не предоставляет, сохранить screenshot штатным tool и отдельно проверить файл и manifest. Нативный `devicectl` capture также доступен при поддержке выбранного target.

Один активный способ установки на каждого агента: standalone либо plugin. Не создавать второй экземпляр автоматически при обновлении и не перезаписывать локальные изменения пользователя.

Первичные источники: [Claude Code skills](https://code.claude.com/docs/en/skills), [plugins](https://code.claude.com/docs/en/plugins), [marketplaces](https://code.claude.com/docs/en/plugin-marketplaces).
